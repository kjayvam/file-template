# 보안 개발 가이드

## 개요

안전한 애플리케이션 개발과 데이터 보호를 위한 내부 보안 지침입니다. 외부 취약점 제보 정책은 루트의 [SECURITY.md](../../SECURITY.md)를 참고하세요.

## 1. 비밀 값 및 환경 변수 관리

- **커밋 금지**: API 키, DB 비밀번호, JWT 시크릿 등 모든 비밀 값은 절대 Git에 커밋하지 않습니다.
- **`.env.example` 동기화**: 새 환경 변수를 추가할 때는 실제 값 없이 키 이름과 설명만 [`.env.example`](../../.env.example)에 기록합니다.
- **코드 하드코딩 금지**: 소스 코드 내부(`src/`)에 테스트용 토큰이나 임시 비밀번호를 상수로 남겨두지 않습니다.

## 2. 인증 및 권한 관리 (AuthN & AuthZ)

- **비밀번호 저장**: 평문 저장을 절대 금지하며, `bcrypt`, `argon2` 등의 강력한 단방향 해시 알고리즘과 솔트(Salt)를 사용합니다.
- **세션/토큰 수명**: Access Token은 짧은 유효 기간(예: 15분~1시간)을 두고, Refresh Token은 안전한 저장소(HTTP-only 쿠키 또는 보안 스토리지)에 보관합니다.
- **최소 권한의 원칙**: 사용자 및 시스템 계정은 작업 수행에 반드시 필요한 최소한의 권한만 부여합니다.

## 3. 입력값 검증 및 인젝션 방지

- **SQL Injection 방지**: Raw SQL 문자열 결합(`query + input`)을 절대 사용하지 않고, 반드시 파라미터화된 쿼리(Prepared Statement) 또는 ORM을 사용합니다.
- **XSS (Cross-Site Scripting) 방지**: 사용자 입력을 브라우저에 렌더링할 때 기본적으로 이스케이프 처리하며, 불가피한 HTML 렌더링 시 살균(Sanitization) 라이브러리를 사용합니다.
- **요청 유효성 검증**: 서버 측에서 모든 요청 본문(body)과 쿼리 파라미터의 타입 및 길이를 엄격히 검증합니다.

## 4. 통신 및 데이터 전송

- 프로덕션 환경의 모든 외부 통신은 HTTPS/TLS를 필수로 적용합니다.
- CORS 정책은 필요한 도메인만 허용하도록 명시적으로 설정합니다 (와일드카드 `*` 지양).

## 5. 의존성 취약점 관리

- 정기적으로 의존성 패키지의 취약점을 점검합니다 (`npm audit` 등).
- 공식적으로 지원 종료(EOL)되었거나 보안 패치가 중단된 라이브러리는 대체품으로 마이그레이션합니다.
