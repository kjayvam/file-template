# 용어 사전 (Glossary)

## 개요

프로젝트 전반(기획, 설계, 개발, 커뮤니케이션)에서 사용하는 표준 도메인 용어와 약어를 정리합니다. 팀원과 AI 에이전트 간의 용어 혼선을 방지하고 코드 명명 일관성을 유지하는 데 목적이 있습니다.

## 도메인 및 비즈니스 용어

| 용어 (한글) | 영문 표기 | 정의 및 설명 | 비고 / 예시 |
| --- | --- | --- | --- |
| **사용자** | User | 서비스를 이용하는 모든 가입 계정 | `src/types/user.ts` |
| **인증** | Authentication (AuthN) | 사용자의 신원(ID/PW, 토큰 등)을 확인하는 과정 | 로그인, OAuth2 |
| **인가** | Authorization (AuthZ) | 인증된 사용자가 특정 리소스에 접근할 권한이 있는지 검증하는 과정 | 역할 기반 권한(RBAC) |
| **워크스페이스** | Workspace | 프로젝트 또는 팀 단위의 작업 공간 컨테이너 | |

## 시스템 및 아키텍처 용어

| 용어 | 영문 표기 | 정의 및 설명 | 비고 |
| --- | --- | --- | --- |
| **마이그레이션** | Migration | 데이터베이스 스키마의 형상 관리 및 변경 작업 | `migrations/` |
| **시드 데이터** | Seed Data | 개발 및 테스트 환경 구축을 위해 사전에 삽입하는 초기 기초 데이터 | `scripts/seed-db.sh` |
| **ADR** | Architecture Decision Record | 중요한 아키텍처 및 기술적 의사결정을 기록한 문서 | `docs/adr/` |
| **MCP** | Model Context Protocol | LLM 및 AI 에이전트가 외부 도구/데이터와 상호작용하기 위한 개방형 프로토콜 | `.mcp.json` |

## 규칙

- 새로운 개념이나 도메인 기능이 추가될 때, 코드 작성 전 용어 사전에 표준 명칭을 먼저 정의합니다.
- 변수명, 함수명, DB 컬럼명, API 엔드포인트 명명 시 이 사전에 등재된 영문 표기를 반드시 준수합니다.
