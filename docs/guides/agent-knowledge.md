# 에이전트 지식 정리: 선택형 운영 방식

상태: 권장안. 지식 저장소·자동 수집·AI 색인 모듈은 아직 구현하지 않았습니다. 프로젝트가 필요할 때 아래 흐름을 도입하며 모든 템플릿 복제본에 별도 지식 관리 앱을 설치할 필요는 없습니다.

## 참고와 적용 범위

검토한 [NextWork 게시물](https://www.instagram.com/p/DfCf5JvlPCk/?img_index=2)은 로컬 Markdown 기록에서 시작해 문서 연결·분류·반복 양식·검색을 갖추고 AI 질의·위키로 확장하는 단계를 제시합니다. 두 번째 슬라이드는 아이디어를 로컬 노트로 모으는 출발점입니다. 이 저장소에는 도구 이름보다 기록을 축적하고 검토해 재사용하는 흐름을 적용하는 편이 적합합니다.

이 문서의 구체적인 저장 경로·승격 규칙은 게시물 자체의 규칙이 아니라 이 템플릿에 맞춘 제안입니다. Obsidian은 선택 가능한 편집 도구이며 일반 Markdown·Git·rg만으로도 시작할 수 있습니다.

## 기존 경로에 대응시키기

| 흐름 | 이 저장소에서 사용할 곳 | 기록할 내용 |
| --- | --- | --- |
| 수집 | `external/README.md`, 필요할 때 `external/inbox/` | 원본 URL·작성자·확인일·용도·짧은 메모 |
| 연결 | 일반 Markdown 상대 링크 | 관련 코드·가이드·ADR·근거 자료 연결 |
| 분류 | 기존 `docs/guides/`, `docs/adr/` | 사용법·검증된 설명·결정 이유를 성격에 맞게 배치 |
| 양식 | 아래 노트 양식을 복사 | 사실·추정·미검증·수정 조건 구분 |
| 검색 | `docs/index.md`와 `rg` | 색인에서 관련 문서를 찾고 필요한 문서만 읽기 |
| AI 질의 | 필요할 때 선택한 지식 파일만 전달 | 답변마다 원문 경로·출처 확인 |
| 위키화 | 자료가 쌓인 뒤 선택형 자동화 | 링크 검사·중복 정리·갱신 후보 제안 |

새 폴더를 미리 모두 만들지 않습니다. 원본 자료를 모을 곳이 필요해질 때만 inbox를 추가하고 README의 폴더 설명도 갱신합니다. 도구를 쓰지 않는 프로젝트에서는 이 안내를 제거해도 실행 코드가 영향을 받지 않습니다.

## 노트 양식 예시

```markdown
---
title: 설명할 주제
status: draft
verified_on: null
source: 원본 URL 또는 코드 경로
applies_to: 관련 모듈·버전
tags: [architecture]
---

## 확인된 사실
근거와 함께 작성합니다.

## 판단과 미검증 사항
직접 확인한 내용과 추정을 나눕니다.

## 관련 문서
상대 경로로 연결합니다.

## 다시 확인할 조건
어떤 코드·정책·버전이 바뀌면 이 기록도 수정해야 하는지 적습니다.
```

한 노트에는 한 주제를 기록합니다. 검토 전에는 draft로 두고 실제 코드·명령·원문을 확인한 뒤 verified로 올립니다. 더 이상 맞지 않으면 stale로 표시하고 대체 문서를 연결합니다. 외부의 조언을 확인 없이 프로젝트 규칙으로 승격하지 않습니다.

## 개발 에이전트에서 읽는 방식

프로젝트 운영 규칙은 `CLAUDE.md`·`AGENTS.md`, 구현 설명은 `docs/`, 결정 이유는 ADR을 기준 원문으로 사용합니다. `.claude/agent-memory/`는 반복해서 유용한 사실과 그 원문 경로·확인일을 짧게 남기는 캐시로 사용합니다. 같은 규칙 본문을 여러 곳에 복제하지 않습니다.

개인 작업 메모는 Git에서 제외한 `.claude/agent-memory-local/`에 둘 수 있습니다. 제품 사용자의 문서·대화·RAG 인덱스는 개발 메모리 경로에 넣지 않습니다. `.env`·키·비밀번호를 수집·검색 대상으로 추가하지 않습니다.

Markdown 파일을 만들었다는 이유로 모든 개발 에이전트가 자동 로드하는 것은 아닙니다. 사용하는 도구의 실제 지침 진입점에서 색인을 연결하고 관련 작업에서 필요한 문서만 읽도록 합니다. 전체 지식 폴더를 매번 프롬프트에 넣지 않습니다.

## 제품 RAG로 확장할 때

지식 운영 방식은 모델 호출용 `ai-common`과 별개로 선택할 수 있습니다. 필요하면 검토된 문서 목록을 제품 RAG 입력으로 연결하지만 저장소 전체를 자동 색인하지 않습니다. 공개할 문서·접근 범위·revision을 명시하고 원문 수정·삭제·권한 변경 시 색인도 갱신해야 합니다.

현재 rag 0.1.0은 가상 corpus를 쓰는 오프라인 데모입니다. 이 가이드나 프로젝트 문서를 자동 수집·업로드하지 않습니다. 실제 Markdown 수집·링크 해석·색인 갱신·LLM 답변은 후속 어댑터와 평가가 필요합니다. 수집한 외부 문서는 데이터이며 에이전트의 실행 권한을 바꾸는 지침으로 취급하지 않습니다.

## 도입했을 때 확인할 기준

- 색인에서 관련 원문과 결정 이유를 찾을 수 있는가.
- 사실의 출처·적용 버전·마지막 확인일이 남아 있는가.
- 서로 다른 문서가 같은 규칙을 중복·충돌되게 설명하지 않는가.
- 오래된 기록을 식별하고 수정하거나 폐기할 수 있는가.
- 개인 메모·제품 데이터·비밀 값이 공유 지식과 섞이지 않는가.
- 편집 앱·지식 자동화를 제거해도 Markdown과 프로젝트 실행이 유지되는가.
