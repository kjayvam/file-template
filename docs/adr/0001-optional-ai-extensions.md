# ADR-0001: 프로젝트별로 추가·제거하는 AI 템플릿 모듈

- 상태: 제안
- 작성: 2026-11-04
- 적용 범위: 재사용 가능한 템플릿의 RAG·Agent 모듈
- 구조: [모듈·적용·제거 설계](../guides/ai-extensions.md)
- 검증: [AI 평가 기준](../guides/ai-evaluation.md)

## 배경

이 저장소는 프로젝트별로 필요한 기능을 추가하고 불필요한 기능을 제거하는 출발 템플릿입니다. Rust·React 기본형과 AI가 항상 함께 배포되는 하나의 제품을 만드는 목적이 아닙니다. 별도 AI 서버·독립 콘솔·특정 저장소를 모든 프로젝트에 요구하지 않습니다.

## 결정 제안

1. templates/ 아래에 적용·해제 설명, 모듈 의존 관계, 파일 원본, 공유 연결 지점, 검사 목록을 정리합니다. 추가·제거 도구는 소유 파일 해시와 이름 붙은 연결 블록만 다루는 작은 범위로 유지하고, 범용 코드 생성기는 만들지 않습니다.
2. ai-common, rag, agent, rag-agent 연결, ai-ui, ai-service를 각각 선택합니다. 사용하지 않는 모듈은 대상 프로젝트에 복사하지 않습니다.
3. 작은 프로젝트는 기존 Rust 서버·React 안에 필요한 모듈을 배치합니다. 별도 workspace·서버·콘솔은 프로젝트 요구에 따라 선택합니다.
4. RAG와 Agent는 공통 인터페이스만 공유하고 검색 도구 연결은 별도 모듈로 둡니다. 공급자·저장소는 교체 가능한 어댑터로 둡니다.
5. 제거할 때 모듈 소유 파일뿐 아니라 라우트·의존성·설정·테스트·CI 등록을 함께 정리합니다. 사용자 변경과 데이터는 자동 삭제하지 않습니다.
6. 평가 항목과 문턱값은 선택한 모듈·배치·용도에 맞춰 구성합니다. 문서의 수치는 예시이며 모든 프로젝트에 고정하지 않습니다.

## 배치 선택

| 상황 | 출발 구성 |
| --- | --- |
| AI 불필요 | 현재 기본형만 사용 |
| 소규모 RAG 앱 | 기존 backend의 ai-common+rag, 필요한 React 화면 |
| 도구 자동화 | ai-common+agent; RAG·UI는 제외 가능 |
| 검색을 쓰는 Agent | rag·agent와 연결 모듈 |
| 부하·격리 요구가 큰 앱 | 필요한 기능만 별도 서비스·workspace로 이동 |

Cargo feature나 런타임 비활성화는 설치된 기능을 켜고 끄는 수단입니다. 템플릿 제거는 코드·의존성·연결 설정까지 정리하는 별도 작업입니다. 독립 서비스 전환도 기존 수정 코드를 보존하며 경로·통신·신원 전달을 검토해야 하는 작업입니다.

## 검증과 한계

모듈의 추가·제거 후 남은 기능의 빌드·검사와 끊어진 참조를 확인합니다. 모듈 원본·예제를 제거해도 프로젝트가 동작해야 합니다. 선택하지 않은 기능의 평가는 적용 범위 밖으로 기록하고 선택한 기능의 검사 누락과 구분합니다.

실제 모델·영속 저장소·운영 인증은 선택 시 구현·평가합니다. 현재 ai-common·rag 0.1.0의 소스 원본·선택형 mock 라우터·추가/제거 도구·임시 프로젝트 검증을 구현했습니다. JSON 원본 목록과 적용 당시 해시로 소유권을 추적하며 변경된 파일의 자동 제거는 거부합니다. Agent·UI·실제 공급자·제품 지식 자동화는 후속 범위입니다.
